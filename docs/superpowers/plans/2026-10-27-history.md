# History of Parsed Results Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save each successful parse on the production site to Postgres and show the last 7 days on a public read-only History page, with the flood protection the spec describes.

**Architecture:** A small `lib/history*` family: a pure scrubber, a domain module (gate, record mapping, `saveEntry`), a Postgres store for the app role, and a separate purge module for the delete-only role. The parse route saves after the response through `after()`; a daily cron route purges. The production rate limit is a stricter number in the existing in-app limiter, with the edge rule set by hand in the Vercel dashboard.

**Tech Stack:** Next.js 16, TypeScript, Jest + Testing Library, Playwright, `@neondatabase/serverless` (new), Vercel Cron.

**Spec:** `docs/superpowers/specs/2026-10-27-history-design.md` (approved, decisions in its "Decisions for Mark").

## Global Constraints

- Next.js 16: read the relevant guide in `node_modules/next/dist/docs/` before framework-level code (`AGENTS.md`). `next.config.ts` has `cacheComponents: true`.
- History is on only when `process.env.VERCEL_ENV === "production"` and `HISTORY_DATABASE_URL` is set. Otherwise no database connection is ever opened.
- Saved fields, exactly: `passenger_name`, `pickup_location`, `dropoff_location`, `pickup_time`, `mobility`, plus `created_at`. Never the raw note, `notes` or `missing_fields`. Scrubbed text is replaced with `[removed]`.
- Constants in `lib/config.ts`: retention 7 days, page row cap 200, daily save cap 2,000, page revalidate 60 s, production rate limit 3 per 60 s (fourth refused), development and preview stay 10.
- Database roles: app role `INSERT, SELECT`; purge role `SELECT, DELETE`. The only `DELETE` in the code is in `lib/history-purge.ts`.
- Purge: `GET /api/history/purge`, `Authorization: Bearer $CRON_SECRET`, 401 otherwise, daily cron, production only.
- History page: public, read-only, `noindex`, cached 60 s, copy says entries are public, kept 7 days, contact details removed.
- Repo conventions: tunables in `lib/config.ts`, URLs in `lib/routes.ts`, user-facing text in `lib/messages.ts`, logs carry an error type only (never entry contents), tests sit next to the code, `npm run check` passes before every commit.
- **Commit messages must not mention Claude or Anthropic and carry no Co-Authored-By lines.** Author is Mark Guerrero.
- The pre-commit hook runs `npm run check` over the whole folder, including untracked files.

## Review Focus

1. **No database or a broken one in production** must never change a parse (Task 5: save throws, store missing, `after` unavailable).
2. **A trip that scrubs down to nothing** (name is an email, other fields empty) is not worth saving (Task 3).
3. **Hostile text on the public page** (`<img onerror>`, very long names) renders as text only (Task 8).
4. **A missing client IP header in production** must not put every visitor in one 3-a-minute bucket and lock everyone out (Task 6).
5. **The 7-day boundary**: a row exactly at the cut-off is treated the same by the page query and the purge (Tasks 3 and 7).
